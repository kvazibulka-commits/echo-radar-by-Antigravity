# ЭХО — стандарты качества

## Когда использовать

- Пишешь или ревьюишь код сервера, шаблонов, Kotlin.
- Решаешь, как обработать ошибку, валидировать вход, хранить секрет.
- Готовишь фичу к коммиту или релизу.
- Споришь о производительности, размере ответа, частоте поллинга.

## Безопасность: база, которая не обсуждается

1. **Секреты только вне кода.** `echo_config.json`, `deploy_token.txt`, ключи —
   в gitignored-файлах или env. В коде — ни токенов, ни PAT, ни ключей Gemini.
2. **Авторизация на всех мутациях.** Новый POST → в `PROTECTED_PATHS`. Внешний
   клиент обязан предъявить токен; LAN-обход — только для реального LAN.
3. **Не доверяй клиенту.** Любой текст с границы: `sanitize_text`, лимит длины,
   проверка `is_junk_track`, нормализация зоны. Числа — `float`/`int` в try.
4. **Экранируй всё, что попадает в HTML.** `esc()` в шаблонах; никаких
   `innerHTML = userText`, никаких JSON в `onclick`.
5. **Ограничивай размеры.** Тело ≤ 2 МБ, обложка ≤ 1.5 МБ, текст ≤ 160,
   послание ≤ 400. Проверяй `Content-Length` до чтения.
6. **CORS — только свой origin.** `Access-Control-Allow-Origin: *` с cookies — дыра.
7. **Не логируй секреты и персональные данные.** Токен печатается один раз в
   консоль сервера — это осознанное исключение для локального оператора.
8. **Cookie токена:** `HttpOnly`, `SameSite=Lax`, `Secure` за HTTPS.
9. **Служебные заголовки:** CSP, `X-Frame-Options: DENY`, `nosniff`,
   `Referrer-Policy: no-referrer`, `Permissions-Policy`.
10. **Токен не отдаётся внешнему клиенту** в `serverMeta`; только локальному пульту.

Красные флаги в ревью: `eval`, `exec`, `pickle` из сети, `shell=True`,
`verify=False`, `Access-Control-Allow-Origin: *` с credentials, `innerHTML` с
данными, токен в строке подключения, `except: pass` вокруг записи в БД.

## Python (сервер)

- Только стандартная библиотека в рантайме; новые зависимости — обоснованно.
- Один файл `echo_server.py` — это осознанно; не плоди модули без нужды.
  Вспомогательные скрипты — в `tools/`, тесты — в `tests/`.
- Типизация в сигнатурах; `from __future__ import annotations` уже включён.
- Вход нормализуй на границе (handler), а не в глубине бизнес-логики.
- Ошибки: `logger.warning` для ожидаемых сбоев (сеть, Gemini), `debug` для шума;
  не глотай исключения там, где обещан результат.
- Соединение SQLite всегда закрывай; используй `with DB_LOCK` для записи.
- Не блокируй HTTP-поток дольше ~0.5 с без необходимости; тяжёлое — в executor.
- Никаких `print` в сервере — только `logger`.

## Kotlin (Android)

- Состояние — `StateFlow` в репозитории; экран не хранит копию бизнес-данных.
- Сеть и диск — `Dispatchers.IO`; UI-колбэки — `Dispatchers.Main`.
- Строки интерфейса — на русском, без захардкоженных URL и токенов.
- Новые поля сети парси через `opt*` с дефолтом; отсутствие поля не должно ронять экран.
- Мелкие изменения: локальной сборки нет, ошибка компиляции всплывёт только в CI.
- Перед пушем мысленно проверь импорты и типы — компилятор доступен лишь в Actions.
- Медиа-перехват невозможен без доступа к уведомлениям: проверяй его и веди
  пользователя в настройки; «Поделиться» принимай только как text/plain.
- Разрешения (гео, уведомления) пересчитывай в `onResume`: `remember` в Compose
  навсегда кэширует первый ответ и создаёт «неисчезающую плашку».
- Любой асинхронный плеер/сеть с индикатором загрузки обязан иметь таймаут:
  состояние «ЗАГРУЗКА...» не должно переживать ошибку.
- **StateFlow без потребителя — баг.** Если состояние приходит в репозиторий, но
  ни один экран его не собирает (`incomingReaction`), пользователь этого не увидит.
  Проверяй: у каждого публичного `StateFlow` есть `collectAsState()` и UI-ветка.

## JavaScript (шаблоны)

- `'use strict'`, IIFE, `var/let` последовательно; без библиотек.
- Данные — только через `textContent`/`esc()`; сборка HTML — из проверенных частей.
- Один делегированный обработчик `click` на `[data-action]`.
- Сетевые ошибки показывай тостом, не оставляй пустой экран.
- Поллинг: 2.5 с, backoff до 7 с, пауза при `document.hidden`.
- Не добавляй внешние CDN, кроме уже разрешённого Leaflet (`unpkg.com`).

## Бюджеты производительности

| Метрика | Бюджет |
|---|---|
| `GET /api/state` локально | p95 < 50 мс, payload < 100 КБ |
| `POST /api/signal` | ответ < 1 с при живом Gemini, иначе фоллбэк ≤ 5 с |
| Сонар | 30 fps, без роста памяти за 10 минут |
| Поллинг | 1 запрос / 2.5 с на клиента; скрытая вкладка — 0 |
| APK | < 12 МБ |
| Первый рендер PWA | < 1.5 с на 4G, без блокирующих шрифтов |
| Память сервера | обложки ≤ 48 × 1.5 МБ, кэши ≤ 500 записей |

Превысил бюджет — объясни в PR/коммите, почему это оправдано.

## Матрица состояний UI

Каждый экран обязан иметь все пять состояний:

| Состояние | Что показываем |
|---|---|
| Загрузка | скелет/подпись «Сонар сканирует…», без пустого экрана |
| Пусто | поэтичная подпись + действие («Включите трек…») |
| Ошибка | что случилось и что сделать («Сервер не отвечает — проверьте адрес») |
| Офлайн | статус-точка серая/красная, последние данные остаются на экране |
| Успех | данные + мягкий тост, если действие инициировал пользователь |

Нельзя: «Нет данных», «Ошибка», «Loading…», бесконечный спиннер без выхода.

## Тестовая пирамида

1. **Юнит (`tests/test_echo_server.py`)** — математика резонанса, фильтры, зоны,
   плейлист, LRU, rate limit, видимость откликов. Быстро, без сети.
2. **Дым (`tools/smoke_test.py`)** — контракт API, авторизация туннеля, заголовки,
   фильтр мусора, нормализация зоны, 404. Запускается против живого сервера.
3. **Визуал (`tools/cdp_shot.py`)** — мобильный 390×844 и десктоп, ошибки JS,
   наличие ключевых элементов, deep links.
4. **Ручная проверка** — реальный телефон/эмулятор: перехват плеера, вибрация,
   установка APK, поведение в фоне.

Новая фича без теста уровня 1–3 — не готова.

## Definition of Done

- [ ] Работает по сценарию и не ломает соседние экраны.
- [ ] Все пять состояний UI покрыты.
- [ ] Тексты в тоне ЭХО, без рекламных штампов.
- [ ] Вход валидирован, выход экранирован, секретов в диффе нет.
- [ ] Юнит-тесты и smoke-тест зелёные.
- [ ] Скриншот 390 px без ошибок JS.
- [ ] Производительность в бюджете (payload, fps, батарея).
- [ ] README/CHANGELOG обновлены, новый файл добавлен в `FILES_TO_COMMIT`.
- [ ] Сборка APK прошла в Actions, APK скачан.
- [ ] Для релиза: тег, релиз, APK-ассет, sha256.

## Анти-паттерны ЭХО

| Анти-паттерн | Почему плохо | Как надо |
|---|---|---|
| Лайки и счётчики | превращает присутствие в соцсеть | отклик-символ без числа |
| Точные координаты | раскрывает человека | джиттер + зона |
| Пустой экран при ошибке | пользователь не знает, что делать | текст + действие |
| Поллинг без паузы | батарея и лишние запросы | `document.hidden` |
| Новый цвет по месту | расползание палитры | токен в обоих клиентах |
| Секрет в коде «на время» | утечка навсегда | файл/env |
| Токен в логах | утечка в тикеты | маскировать |
| Бесконечный `while True` без sleep | CPU | sleep/await |
| Коммит «всё сразу» | невозможно откатить | маленькие коммиты |
| Пуш без тестов | CI красный, APK старый | локальные проверки |

## Релиз и откат

1. Проверить `main` и зелёный Actions.
2. `python deploy_build.py --message "..."` — APK скачан.
3. `python tools/publish_release.py --tag vX.Y.Z` — релиз с APK.
4. Проверить sha256 ассета и страницу релиза.
5. Откат: вернуть предыдущий коммит через Git Data API (`force` только осознанно),
   пересобрать, выпустить новый тег. Старые теги не перезаписывать.
6. Инцидент безопасности: сменить `echo_token`, перезапустить сервер, разослать
   новый токен клиентам, отозвать скомпрометированные PAT.
