## 🏛️ РАЗДЕЛ 1. МАНИФЕСТ И НЕПРЕЛОЖНАЯ ФИЛОСОФИЯ

> *«Ты видишь не людей вокруг.*  
> *Ты видишь музыку, которая сейчас живёт вокруг тебя.»*

### 1.1. Концепция Slow Tech («Тихие технологии»)
ЭХО создаётся как полная противоположность коммерческим соцсетям, паразитирующим на дофаминовых петлях, бесконечном скролле, борьбе за лайки и социальном сравнении:
- **Никаких профилей и лиц:** Нет аватарок, юзернеймов, биографий, возраста, пола, фото и статусов.
- **Никаких счётчиков тщеславия:** Нет подписчиков, лайков, просмотров, рейтингов «топ слушателей».
- **Никакого навязчивого общения:** Нет личных сообщений (DM), чатов, комментариев, запросов в друзья.
- **Только звук и присутствие:** Сонар показывает **музыку**, приблизительную дистанцию и поэтический образ настроения. Отношения строятся исключительно через созвучие вкусов.
- **Slow Interface:** Тёмный ночной фон (`#08080C` – `#0A0A0F`), мягкое неоновое свечение, аналоговая эстетика винила, отсутствие кислотных баннеров и всплывающей рекламы.

## ⏳ РАЗДЕЛ 2. ХРОНОЛОГИЧЕСКАЯ ЭВОЛЮЦИЯ ПРОЕКТА (v1 → v11)

### 🌑 ЭТАП 1: Зарождение концепции (Проект «Echoes», v1)
* **Исходная идея:** Веб-радар присутствия вокруг слушателя.
* **Стек:** HTML5 Canvas + FastAPI + SQLite + симуляция ботов.
* **Что было разработано:**
  - Алгоритм полярной проекции координат на круг сонара.
  - Понятие «Резонанса» между слушателями (в v1 — статические константы).
  - Первичный онбординг с манифестом тишины.
  - Попытки чтения музыки через заголовки окон Windows, Last.fm API и Windows GSMTC.

### 🌓 ЭТАП 2: Аудит и архитектурный кризис прототипа (v2 – v4)
* **Выявленные проблемы прототипа:**
  - Заголовки окон Windows не читали Яндекс Музыку в браузере (Chromium не выводил трек в title вкладки).
  - GSMTC на Windows периодически зависал по тайм-ауту.
  - Last.fm требовал VPN, который конфликтовал с российскими музыкальными сервисами.
  - В БД отсутствовали нужные поля схемы (`is_playing`), вызывая SQL-ошибки.
  - При отсутствии музыки симулировался фантомный прогресс «старого трека», создавая иллюзию работы.
* **Принятые решения:**
  - Разделение ответственности: нативный Android-клиент для мобилок, выделенный companion-скрипт для ПК, лёгкий REST-сервер.
  - Создание локального тестового стенда (`echo_server.py`, `echo_pc.py`, PWA `/app`).

### 🌔 ЭТАП 3: Переход на Android Jetpack Compose (v5 – v8)
* **Новая архитектура приложения:**
  - 4 чистых экрана: **ЭХО** (Сонар), **ДЕКА** (Винил-проигрыватель), **ОТЗВУКИ** (Хроника), **ТАЙНИКИ** (Капсулы).
  - `EchoMediaListenerService` (`NotificationListenerService`): 100% надёжный перехват текущего трека из Яндекс Музыки, VK, Spotify, YouTube Music, Звука без рут-прав и без костылей.
  - Процедурный Canvas винилового диска с тонармом, анимацией вращения 33⅓ RPM и скретчем.
  - Двухсторонняя интеграция: отправка сигнала `POST /api/signal`, синхронизация `GET /api/state`.
  - Внедрение токена безопасности `X-Echo-Token`.

### 🌕 ЭТАП 4: Звуковой дизайн, тайники и резонанс (v9 – v10)
* **Фичи:**
  - Тактильный виброотклик (`Haptics`) и процедурный аналоговый звук виниловой иглы (`EchoSoundManager`).
  - Механика тайников заведений «Proof-of-Music»: кофейни и бары прячут треки и послания, которые открываются только тем, у кого резонанс созвучия $\ge 70\%$.
  - Игла в унисон (`needle_sync` / «Слушать вместе»): синхронное вращение пластинки с далёким незнакомцем.
  - Облачный туннель Cloudflare (`echo_tunnel.py`): мгновенный доступ к радару из любой точки мира без белого IP.
  - GitHub Actions CI/CD пайплайн для автоматической компиляции APK за 90 секунд.

### 🌌 ЭТАП 8: Версия 14 — Акустические Созвездия (Acoustic Constellations) и Плавный Zoom/Pan
* **Инсайт пользователя:** Линейная шкала радиоприёмника (88–108 МГц) противоречит пространственной сути приложения («на подсознательном уровне — ерунда»).   - **Акустические Созвездия (Acoustic Constellations):** Тончайшие небесные нити соединяют созвучные треки ($\ge 70\%$, близкий жанр или ключ) в грациозные созвездия района (стиль Sky Guide / Star Walk). ## 📐 РАЗДЕЛ 4. ТЕКУЩИЕ АРХИТЕКТУРНЫЕ СТАНДАРТЫ

### 4.1. Цветовая палитра (Echo Tokens)
- **Deep Space Black:** `#08080C` — фон приложения и сонара.
- **Surface / Card:** `#11161F` (обводка `#1E2838`).
- **Signal Cyan:** `#00F0FF` (`#38BDF8`) — цвет эфира, сканирующего луча, активных табов и маяка пользователя.
- **Acoustic Gold:** `#FBBF24` — цвет высокого резонанса ($\ge 80\%$), тайников, водных кругов и кнопки действия.
- **Dissonance Slate:** `#64748B` — цвет акустического контраста ($< 50\%$).
- **Ghost White:** `#94A3B8` с прозрачностью 0.42 — призрачные следы прошлого.

### 4.2. Правила отображения Сонара
1. **Пассивное состояние:** 0 соединительных линий. Только кольца сонара, нить ночной реки, сканирующий луч и дышащие круги.
2. **Резонансные волны (Ripples):** Для точек $\ge 80\%$ рассчитываются волны по фазе фотонов:
   $$r_{\text{ripple}} = r_{\text{disc}} + 18\,\text{dp} \cdot \text{phase}, \quad \alpha = (1 - \text{phase}) \cdot 0.22$$
3. **Anti-Overlap Relaxation:** Перед отрисовкой и обработкой кликов координаты прогоняются через алгоритм отталкивания маркеров при $d < 28\,\text{dp}$.
4. **Фокус:** По тапу выбирается одна пластинка $\rightarrow$ к ней натягивается луч $\rightarrow$ снизу открывается карточка $\rightarrow$ повторный тап или тап в пустоту закрывает выбор.
