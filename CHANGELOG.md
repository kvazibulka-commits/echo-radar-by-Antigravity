## 3.2.0 — «Яндекс Музыка»

### Android

- **Перехват медиа-сессий стал надёжным:** сервис опрашивает активные сессии раз в
  2.5 секунды и дополнительно читает `Notification.EXTRA_MEDIA_SESSION`, поэтому
  Яндекс Музыка видна даже когда уведомление не обновляется при смене трека.
- **Проверка и запрос доступа к уведомлениям:** на ДЕКЕ показывается статус
  («ЭХО слушает плееры» / «ЭХО пока не видит Яндекс Музыку») и кнопка
  «Разрешить доступ» → системный экран доступа.
- **«Поделиться → ЭХО»:** приложение принимает `ACTION_SEND` text/plain из Яндекс
  Музыки, разбирает «Исполнитель — Трек», отбрасывает ссылку и отправляет трек в эфир.
- **Ручная трансляция:** лист «ТРАНСЛЯЦИЯ ИЗ ЯНДЕКС МУЗЫКИ» — вставить ссылку или
  «Исполнитель — Трек», кнопка «В эфир», переход в Яндекс Музыку.
- Плей/пауза без доступного превью открывает трек в Яндекс Музыке; жанровый бейдж
  скрыт, пока трек не определён.
- Версия приложения: `0.2.0-alpha` (versionCode 2).

### Сервер

- Версия `3.2.0`. Контракт API не изменился.

## 3.1.0 — «Ночной пульт» (KIMI edition)

### Безопасность

- **Критично:** публичный туннель больше не обходит авторизацию. `cloudflared`
  подключается к серверу с `127.0.0.1`, из-за чего старый `_check_token()` считал
  любой запрос из интернета локальным и пропускал его без токена. Теперь запросы с
  `CF-Connecting-IP` / `CF-Ray` / `X-Forwarded-For` / `X-Real-IP` / `Forwarded`
  считаются внешними и требуют токен; LAN-обход остался только для настоящей
  домашней сети.
- `GET /api/state` и `GET /api/playlist` защищены токеном для внешних клиентов
  (Android присылает `X-Echo-Token`, браузер — cookie после открытия `/`).
- `/api/needle_sync`, `/api/send_warmth`, `/api/wave_impulse` добавлены в список
  защищённых эндпоинтов.
- Удалён захардкоженный токен `1c13ee…` из сервера, `echo_pc.py` и Android-клиента.
  Новый токен генерируется через `secrets.token_hex(16)` и сохраняется в конфиг;
  существующий токен из `echo_config.json` продолжает работать.
- Cookie токена: `HttpOnly`, `SameSite=Lax`, `Secure` при `X-Forwarded-Proto: https`.
- `deploy_build.py` больше не содержит GitHub PAT. Токен берётся из `GITHUB_TOKEN`
  или `deploy_token.txt`; путь проекта определяется относительно скрипта.
- Шаблоны переведены на экранирование (`esc()`), убраны `onclick='openPassport(${JSON.stringify(...)})'`
  и вставки пользовательских строк в `innerHTML` — устранены DOM-XSS и поломка
  вёрстки на треках с кавычками.

### Надёжность и гигиена данных

- Исправлен `NameError: sys` в `EchoServer.handle_error` (сервер падал на обработке
  разрыва соединения).
- `infer_track_acoustics` / `find_archetype_in_library` / `record_history_if_unique`
  устойчивы к `NULL` в базе (раньше `mood_label=None` ронял весь `/api/state`).
- Фильтр служебных медиа-потоков `is_junk_track()`: `chrome-extension://`,
  `offscreen.html`, `file://`, пустые названия, заголовки вкладок вида
  `… | SSR (308046B0AF4A39CB)`. Работает в `/api/signal`, в Windows SMTC и при
  очистке базы на старте.
- Неизвестные зоны нормализуются к известным (`Городской сектор` → `Вечерняя улица`).
- Постоянные маяки `sig_*` всегда «живые» (не превращаются в призраков после
  перезапуска сервера).
- Лимиты: тело запроса ≤ 2 МБ, обложка ≤ 1.5 МБ, текст ≤ 160 символов.
- `DEVICE_COVERS` — LRU на 48 обложек вместо бесконечного словаря.
- Скользящее окно rate-limit: 240 GET состояния и 90 POST в минуту на IP.
- Уникальные монотонные id откликов (`next_event_id()`), без коллизий при
  параллельных запросах.
- Кэш шаблонов по `mtime`: правки `templates/*.html` подхватываются без рестарта.
- `ThreadingHTTPServer` с `daemon_threads=True`, понятные 404/413/429 ответы.
